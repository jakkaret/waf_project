📖 เจาะลึก 4 ส่วนหลักของระบบ

1
Security Dashboard — สรุปความปลอดภัยและ Anomaly Scoring
Fast Analytics & Visuals
🧠 Main ▶

มีไว้ทำไม: เพื่อให้ผู้ดูแลระบบเห็นภาพรวมทราฟฟิก ตรวจจับแนวโน้มการโจมตี (Threat Vectors) และประเมินสถานะของระบบแบบ Real-time

เบื้องหลังการทำงาน: React Frontend ยิง Polling ไปที่ GET /api/analytics/stats ทุก 10 วินาที FastAPI จะยิง Aggregate Query ตรงเข้า ClickHouse Database ซึ่งใช้โครงสร้าง Columnar Storage ทำให้ Query ข้อมูลล้านแถวได้ภายในเวลา <10ms

สแตกและเครื่องมือที่ใช้: React 18, TailwindCSS, Recharts, FastAPI (Python 3.11), ClickHouse MergeTree, Docker
2
Traffic Log (Attack Viewer) — บันทึกทราฟฟิกและหลักฐานการโจมตี
Forensics & Incident Investigation
🌐 Edge ▶

มีไว้ทำไม: สำหรับสืบสวนเชิงลึก (Forensic Analysis) ดูว่า Request ไหนโดนบล็อกด้วย ModSecurity Rule ID อะไร และสามารถ Export CSV ไปใช้เป็นหลักฐานได้

เบื้องหลังการทำงาน: เมื่อ Request วิ่งผ่าน Nginx WAF ตัว ModSecurity CRS Engine จะตรวจ Header และ Body ถ้า Anomaly Score ≥ 10 จะเขียน Log ลง /var/log/modsecurity/audit.log จากนั้น Python Log Forwarder จะส่งแบบ Streaming เข้า ClickHouse ตาราง security_audit_logs

สแตกและเครื่องมือที่ใช้: OWASP ModSecurity Core Rule Set (CRS 3.3/4.0), Nginx Audit Log, Python Log Forwarder, ClickHouse
3
Web Origin & Tunnel — การจัดการเซิร์ฟเวอร์และตั้งค่า DNS
Routing & Automated DNS Verification
🧠 Main ▶

มีไว้ทำไม: ให้เจ้าของเว็บไซต์นำโดเมนและ IP ของเซิร์ฟเวอร์จริง (Origin) มาผูกเข้ากับระบบ WAF เพื่อรับการปกป้องโดยไม่ต้องย้ายโฮสติ้งเดิม

เบื้องหลังการทำงาน: ข้อมูล Origin จะบันทึกลง AWS DynamoDB / LocalStack จากนั้น Background Worker (dns_verification_worker.py) จะใช้ dnspython ตรวจสอบ DNS Record ในอินเทอร์เน็ตจริง เมื่อชี้ CNAME ถูกต้องจะเปิดใช้งาน Routing และขอ SSL อัตโนมัติผ่าน Caddy

สแตกและเครื่องมือที่ใช้: AWS DynamoDB, FastAPI, dnspython, Caddy 2 SSL Auto-provisioning
4
CDN & Edge Nodes — เครือข่าย Edge Caching และการซิงก์กฎความปลอดภัย
Zero-Downtime Rule Sync & Edge Shield
🌐 Edge ▶

มีไว้ทำไม: วางเซิร์ฟเวอร์ไว้ตามภูมิภาค (SG: 45.154.26.91, TH: 178.104.53.123) เพื่อลด Latency แคชข้อมูล Static และสกัดกั้นการโจมตีตั้งแต่ขอบเครือข่าย

เบื้องหลังการทำงาน: สคริปต์ 99-rulesync.sh บน Edge Node จะส่งคำขอเช็ก Checksum Bundle ไปที่ Control API (178.104.53.123:8070) ทุก 5 วินาที เมื่อตรวจพบกฎใหม่ จะโหลด Tarball แตกไฟล์ลง /opt/custom-rules รัน nginx -t แล้วสั่ง nginx -s reload ทันทีแบบ Zero-Downtime!

สแตกและเครื่องมือที่ใช้: Nginx proxy_cache, ModSecurity CRS, Docker Compose, GeoDNS, Bash Rulesync Loop
