2.1 ปัญหา Data Leakage ใน Pipeline เดิม และการค้นพบเชิงลึก

จากการวิเคราะห์โค้ดเดิม พบว่ามีการนำ Payload เสริม 37 รายการมาทำ df_combined = pd.concat([df_csic] + [df_benign_extra]*500 + [df_attack_extra]*500) ซึ่งการคูณข้อมูลซ้ำ 500 เท่าทำให้แถวข้อมูลที่เหมือนกันทุกตัวอักษร 375 แถวไปอยู่ใน Train Set และอีก 125 แถวไปอยู่ใน Test Set ส่งผลให้โมเดลได้ Accuracy สูงเกินจริง (Fake 94%+) จากการท่องจำตัวอย่างเดิม

❌ ปัญหาของ Pipeline และ CSIC 2010 เดิม

  • Exact Row Duplication คูณ 500 เท่า ทำให้เกิด Data Leakage
  • CSIC มี Header Label Noise กว่า 5,400 แถวที่เป็น URL ว่างแต่โดนติดป้าย Attack
  • Path-Length Bias: URL สั้นถูกมองเป็น Attack เพราะ CSIC มีแต่ e-commerce ยาวๆ
  • ขาด Threat Vectors ยุคใหม่ (SSRF, SSTI, NoSQL, Log4j)

✅ วิธีการแก้ไขด้วย Synthetic Data Generator

  • สร้างสคริปต์สังเคราะห์ข้อมูลอัจฉริยะ 35,000+ รายการแบบสุ่มแท้จริง
  • Fuzzing & Mutation (Case variation, URL encode, Comment evasion)
  • Global Deduplication การันตีว่าข้อมูล 60,106 แถวไม่ซ้ำกัน 100% (Zero Leakage)
  • ทดสอบบน Holdout Unseen Test Data 15,027 แถวจริง

2.3 ตารางฟีเจอร์เชิงความปลอดภัย (13 Pure Semantic Security Features)

# Feature Name Type คำอธิบายและวัตถุประสงค์ด้านความปลอดภัย
1special_char_countintนับอักขระอันตราย (' " ; < > \ $ ( ) | ` ^ ~ * # { } [ ]) โดยไม่นับเครื่องหมาย URL ปกติ
2special_char_ratiofloatสัดส่วนอักขระพิเศษต่อความยาวรวม เพื่อ Normalize ข้อมูล
3keyword_matchesintตรวจจับ Attack Keywords (SQLi, XSS, RCE, SSRF, SSTI, NoSQL, Log4j)
4html_tag_matchesintตรวจจับโครงสร้างแท็ก HTML (<script>, <svg>, <iframe>) สำหรับ XSS
5path_traversal_depthintนับความลึกของการย้อนโฟลเดอร์ (../, ..\, ..%2f) สำหรับ LFI/RFI
6quote_unbalancedbinaryตรวจจับ Quote เดี่ยวหรือคู่ที่ไม่ครบคู่ (Sign of SQLi Injection Breakout)
7has_sql_operatorbinaryตรวจจับ Boolean & Set Operator (UNION SELECT, ' OR '1'='1)
8has_ssrf_tokenbinaryตรวจจับ Cloud Metadata SSRF (169.254.169.254, metadata.google)
9has_ssti_nosqlbinaryตรวจจับ Template Injection และ NoSQL ({{...}}, $ne, $gt, ${jndi:)
10is_oversized_payloadbinaryตรวจจับ Request ยาวผิดปกติ (> 2048 bytes) กัน Buffer Overflow
11is_clean_structurebinaryแฟล็กยืนยันว่า Request สะอาด ไม่มีอักขระโจมตีใดๆ เพื่อลด False Positive
12has_excessive_paramsbinaryตรวจจับ Parameter ล้น (> 10 ตัว) สำหรับ HTTP Parameter Pollution
13method_is_postbinaryตรวจจับ HTTP POST Method

3. Layer 1: ModSecurity & OWASP Core Rule Set (CRS v4.0)

ระบบ In-line Fast Path Inspection, Anomaly Scoring Model และการสร้างกฎอัตโนมัติ

Anomaly Scoring Model vs Traditional WAF

ในระบบนี้เราใช้ OWASP CRS Anomaly Scoring Mode (Threshold = 10) โดยแต่ละ Rule ที่ตรวจพบจะบวกคะแนนความเสี่ยง (Anomaly Score) เข้าตัวแปร tx.inbound_anomaly_score และจะบล็อก 403 Forbidden ที่ Phase 2 ทันทีเมื่อคะแนนรวมถึงเกณฑ์ ช่วยลด False Positive ได้อย่างดีเยี่ยมเมื่อเทียบกับการบล็อกแบบ Rule-by-Rule

Score = Critical(5) + High(4) + Medium(3) + Low(2)
Block Action: tx.inbound_anomaly_score >= 10

Auto-Generated SecRule Sample

เมื่อโมเดล ML ตรวจพบภัยคุกคามใหม่ ระบบจะสร้าง ModSecurity Rule ที่ถูกต้องตามหลักไวยากรณ์ Apache SecRule โดยอัตโนมัติ:
